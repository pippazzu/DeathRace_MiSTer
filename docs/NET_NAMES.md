# Netlist format and wire names

## Sheets

`netlist/sheetNN.net` is written the way MAME writes its TTL netlists (for example
`src/mame/atari/nl_tank.cpp`): first every chip on the sheet, by board location, then one line
per wire listing the pins it joins.

```
chip C12 74174              # TTL_74174_DIP(IC_C12)
prom C15 82S123 31          # PROM type and its 6331-31 part number
net  TLC8 C12.4 B12.2       # NET_C(IC_C12.4, IC_B12.2), drawing label first
net  L999 C12.1 E12.1 BOARD # BOARD: driven or read by rtl/deathrac_board.v
net  GND B15.3 B15.6        # GND/VCC tied pins, OPEN floating input, NC drawn stub
```

- A wire that crosses sheets appears on each sheet with the same drawing label, as the
  drawing's off-sheet labels do. The generator joins them by label.
- A chip is declared on every sheet that draws part of it. Gate packages (7400, 7410, ...)
  and the two 74112 halves are split into gates by their DIP pinouts in
  `tools/generate_netlist.py` (`GATE_PINS`, `JK_HALVES`). A pin that is not on any gate of its
  package is an error, which is how L7 pin 11 (really pin 9) was found.
- `netlist/deathrace.overrides` gives `CHIP.PIN LABEL` for every pin wired differently on
  Death Race.

## Wire names in the generated Verilog

`tools/generate_netlist.py` names every wire from its ends, so either end can be found on the
drawing. `n_` goes in front, because some locations start with a digit (13R).
Pins are the physical pin numbers, never gate letters or data-sheet names.

| Wire | Name | Example |
|---|---|---|
| Two ends | driver pin, then load pin | `C15_pin7_E15_pin9` |
| More than two ends, including several pins of one IC | driver pin, then the drawing label | `B15_pin15_TECB` |
| Output that goes nowhere | driver pin, then `NC` | `G15_pin10_NC` |
| Leaves the board (`BOARD`) | driver pin, then the drawing label | `U6_pin12_XC1A` |
| Board input (`BOARD`, no driver on the drawing) | drawing label, unchanged | `L999`, `ECDA`, `MTTA` |

Notes:

- **Loads include Death Race.** A pin that `deathrace.overrides` connects only on Death Race
  counts as a load, so `J10.10` makes `H16_pin13_5ECK1` a several-load wire.
- **Drawing labels keep their polarity prefixes** (5, 6, 1, 2): `5TLC9` is the drawing's own
  name for the inverted TLC9. No `_n` suffix is added, because the prefix already says it and
  the label must match the drawing letter for letter.
- **Board inputs keep their labels**, because `rtl/deathrac_board.v` drives them by name. The
  ports of `deathrac_board` itself are unchanged.
- **TDRG** is the drawing's spelling of TCRG on sheets 8 and 10. The sheets keep it, and
  `ALIASES` joins it to the one wire `C15_pin2_TCRG`.
- **C10 duplicate designator.** Sheet 8 labels its BCNG 7408 "C10", like the 74166 on sheet 6
  (see `docs/ACCURACY.md`). Both keep C10. Their wires stay apart because each is named after
  its own driver.
- **Steering feedback gates** (`P7_pin3_MTNR` and the rest) are found by their label.
- **Counter buses** are not grouped into one bus name: each counter output is its own wire.
- Prose docs (`ACCURACY.md`, `DEATH_RACE.md` and others) quote drawing labels. Find the wire
  name for a label in the table below.

## Chip list

The sorted chip list and the generated IC-type count are at the top of
`rtl/deathrac_board.v`. After any change to the sheets, run `python tools/generate_netlist.py`
and `python tools/ic_count.py`. `python tools/ic_count.py --check` fails when the count is
stale, a chip used in a sheet, override or wire name is missing from the list, or a listed
type disagrees with a sheet's `chip` line.
